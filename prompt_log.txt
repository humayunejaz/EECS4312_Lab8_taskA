We are implementing an appointment slot recommender system.

System description:
The system receives a scheduling day, working hours, a list of busy intervals, a required meeting duration, an optional buffer time, an optional candidate window, and a maximum number of suggestions n. It returns valid appointment slots in chronological order.

Jane Adams: busy professional, trusts automation, wants predictable and stable ordering, automatic conflict handling, and minimal information overload.
Mo Rodriguez: edge user with accessibility needs, wants deterministic behavior, explicit handling of edge cases, and no silent failures.

C1: The system must return appointment suggestions in deterministic chronological order.
C2: The system must reject any slot that overlaps with busy intervals or violates buffer constraints.
C3: The system must return at most n valid slots.
C4: Repeated executions with identical inputs must produce the same ordered slot list.
C5: The system must correctly handle overlapping intervals, adjacent intervals, small gaps, and candidate-window restrictions.
C6: When no valid slot exists, the system must return an empty list rather than failing silently.

AC1: Returned slots must lie within working hours and be chronologically ordered.
AC2: Overlapping and unsorted busy intervals must be normalized before scheduling.
AC3: No returned slot may violate buffer constraints.
AC4: Identical inputs must produce identical ordered outputs.
AC5: No valid availability must result in an empty list.
AC6: The system must return no more than n slots.

Before generating code, review this specification and identify:

2. any ambiguous requirements
3. any unhandled edge cases
